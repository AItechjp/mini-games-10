# BAYLINE — AFTER HOURS

An original coastal-city action game for the browser. This is not a Rockstar/GTA product and does not reuse GTA characters, maps, logos, music, or assets.

## Entry point

`/bayline/` is an independent page. Existing hub entries and other games are not replaced.

## Play

Choose **街へ入る**, then **この章を開始** in the job menu. The objective is marked in gold in the city and on the map. Complete the current chapter and choose the next chapter from **仕事**. Twelve authored chapters combine travel, interaction, combat, defense, driving circuits and escape objectives. The approximately one-hour playtime is a design target, not a measured completion-time guarantee. Optional deliveries, three repeatable races, 24 collectible cases and free exploration remain available after the story.

PC controls: WASD/arrows move or drive; right-drag rotates the camera; left mouse fires; F enters/exits or takes the passenger seat; E held interacts or revives; R reloads; Shift sprints; Space brakes in a vehicle or fires on foot; M opens the map; J opens jobs; Escape opens settings. Cars must slow down before exiting. Touch uses the left stick, right-side camera drag and labelled action buttons; landscape is recommended.

## Two-player sessions without login

The host chooses **2人協力の部屋を作る**, copies the invitation and sends it to one friend. The friend opens the link and presses **参加**. No username, email, password or user account is required. Two people can drive separate vehicles or share driver/passenger seats. The host simulates both players, all cars, opponents and mission progression. A third participant is refused by the game admission protocol.

The invitation contains a cryptographically random 128-bit room code and a host identifier. Knowledge of the invitation grants access to a public Realtime topic: this is a private-by-link casual session, not a fully authenticated competitive server or anti-cheat system. Do not post invitations publicly. Closing the room and creating another rotates the invitation. Communication uses the existing public browser-safe Supabase project configuration, never a service-role or secret key. No database tables, billing settings, authentication settings or existing game backends are changed.

The host must keep the game foregrounded. Mobile/background tab throttling can stall the simulation, and disconnection is surfaced in the UI. Guest state is not saved over the guest's solo profile. Host progress is stored locally; refreshing resumes the saved chapter objective at the garage, not an exact full-world snapshot. Clearing browser data erases this save. Rooms are temporary and not stored in a database.

## Rendering

Three.js 0.180.0 is loaded from the site's existing self-hosted `touge/vendor` deployment directory. City materials, windows, vegetation, vehicles, characters, skies and sea are generated by the code. PBR-style materials, an environment capture, dynamic shadows, emissive lighting, restrained bloom and rain are available. Quality presets expose mobile-friendly rendering. The result is a lightweight original 3D browser game, not AAA photorealism, an Unreal Engine build, or commercial-GTA-scale simulation. The map is an exterior city; there are no explorable building interiors, aircraft, boats or giant licensed asset packs.

## Source layout

- `bayline/core.mjs`: deterministic city data, collisions, driving, enemies, mission state machine, safe save format and compact network snapshots.
- `bayline/world.mjs`: scene and procedural models, material generation, animation, camera and visual effects.
- `bayline/net.mjs`: raw Supabase Realtime v1 WebSocket protocol, room admission, input/state transport, heartbeat and reconnect handling.
- `bayline/game.mjs`: controls, HUD, map, jobs, settings, touch UI, audio, saves and session lifecycle.
- `bayline/index.html`, `bayline/style.css`: Japanese interface and responsive layout.

No ad or analytics scripts are loaded by the new game. Hosting and realtime infrastructure may retain their ordinary service logs. The game's profile save contains progress, cash, upgrades and collectibles, not personal-profile fields.

## Verification

Run `node tests/bayline-core.mjs` for simulation tests. The campaign test uses controlled fixtures to exercise the actual stage handlers; it is not a human one-hour playthrough. `tests/bayline-smoke.mjs` exercises Chromium rendering, keyboard driving, touch viewport bounds and independent-browser connections through the real Supabase service. Screenshots and JSON results are retained in the `bayline-review` workflow artifact. Full-world mutation hooks are restricted to localhost with `?test=1`; the public build exposes only a boolean readiness flag.

Static deployment is handled by the existing main-branch Pages workflow. Do not state that a release is published solely because the feature branch tests pass; verify the deployed URL separately.
